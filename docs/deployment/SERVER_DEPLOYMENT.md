# 服务器部署准备

本文件只定义下一里程碑的前置条件和安全边界。当前尚未获得目标服务器、域名、DNS、SSH 用户、防火墙和备份目的地，因此不得写成服务器已部署或 HTTPS 已完成。

## 部署前必须确认

- 目标服务器的操作系统、CPU 架构、内存、磁盘和受支持的 Docker Engine/Compose 版本。
- 专用非 root 运维用户、SSH 公钥登录和最小 sudo 权限；不得把私钥复制进仓库。
- 正式域名、DNS 管理权限、80/443 入站策略和主机防火墙规则。
- 管理员正式邮箱、离线生成的密码哈希、足够强的会话密钥，以及秘密交付方式。
- PostgreSQL 与对象数据的异机备份目的地、保留周期、加密和恢复演练计划。
- 监控、日志保留、容量告警、更新窗口和事故联系人。

## 预定拓扑

公网只开放 Caddy 的 80/443；Next.js、PostgreSQL 和 S3 兼容存储留在私有容器网络。Caddy 在确认域名后启用自动 HTTPS。数据库迁移作为单次门禁先于应用启动；失败时不启动新应用版本。

服务器部署必须使用独立的生产环境秘密，不复用 `.env.local`。镜像应继续固定版本或进一步改为 digest，并在升级前完成变更审阅、备份和回滚点。

## 服务器验收门禁

- DNS 与证书链有效，HTTP 自动跳转 HTTPS，TLS 配置和安全响应头通过检查。
- 数据库/对象存储无公网监听，管理端无默认凭据，客户端构建中无服务端秘密。
- 迁移、健康检查、公开页面、管理员登录、上传/下载、统计和重启持久化均实测。
- 创建异机备份并在隔离目标完成真实恢复演练。
- 记录镜像版本、最终 Git 提交、部署时间、回滚命令和责任人。

取得上述目标信息并收到 Neil Bauman 明确继续指令后，才创建服务器专用 Compose/Caddy 配置并执行部署。
