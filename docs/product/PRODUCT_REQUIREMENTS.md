# Catnip Skill Hub 产品需求

## 1. 产品身份与定位

- 名称：Catnip Skill Hub / Catnip 薄荷猫 Agent Skill 独立站
- 团队品牌：Catnip 薄荷猫
- 项目负责人和管理员：Neil Bauman
- 定义：由管理员筛选、整理和发布的中文 Agent Skill 网站。

用户以浏览创意内容网站和精品数字商品商店的方式发现 Skill，通过视觉封面、中文传播标题和短介绍理解用途，在详情页查看能力、场景、效果，并下载 ZIP 或生成 Claude Code CLI、Codex CLI 安装命令。Skill 始终是主角；案例只能是详情页中的辅助效果、实测或作品模块，不建立独立案例主线。

## 2. 第一版内容与权限

- 正式资源类型：标准 Agent Skill、Skill Pack。
- 子类型：单项 Skill、原生 Skill 包、编辑组合包。
- 首批目标：10 至 20 个精选资源。
- 未来类型预留：`prompt`、`mcp`、`agent_workflow`、`rule`、`template`；第一版前台不展示。
- 普通访问者无需登录即可浏览、搜索、查看详情、下载 ZIP、复制安装命令。
- 第一版只有管理员可创建、录入、发布、下架；所有资源先为草稿，再由管理员发布。
- 不实现普通用户注册、收藏、评论、评分、用户发布、社区、主页、关注、付费、在线编辑、文件浏览器、子 Skill 选择打包、MCP/Prompt 市场或多语言切换。

可以提供公开的“推荐 Skill”线索表单，字段为 Skill 链接、发现渠道、推荐理由、选填联系方式。线索不自动创建草稿、不自动公开，由管理员人工判断和录入。

## 3. 分类与标签

固定主分类为：VibeCoding 硬件、编程开发、前端设计、产品与项目管理、自动化。每个资源只能有一个主分类，可有多个自由标签。Claude Code CLI、Codex CLI 是兼容信息或标签；ESP32、Arduino、树莓派、传感器、PlatformIO、IoT 是 VibeCoding 硬件下的标签。

## 4. 首页体验

- 气质：图片驱动、灵动、可持续浏览、克制而不呆板的“创意发现 + 精品数字商店”。
- 避免 GitHub 文件列表、传统文档站、满屏炫光/赛博风和技术信息压过视觉发现。
- 结构：文字品牌、未来 Logo 占位、探索、分类、普通顶部搜索、推荐入口、分类胶囊、Skill 瀑布流、默认随机推荐、页脚品牌和来源说明。
- 不放占据大量空间的搜索 Hero，用户应尽快看到内容。
- 卡片展示封面、中文传播标题、一句话介绍、原作者、主分类或标签；阅读量为低优先级。整卡可点击，首页无下载按钮，不强调包技术差别。
- 封面标题负责吸引，一句话介绍负责解释，二者不机械重复。
- 封面可用概念插画、框架/流程图、界面效果、硬件原型、合适的原社区图片、团队实测截图或管理员外部生成后上传的图片；第一版不集成站内 AI 生图。
- 默认从管理员允许的推荐池随机展示，数据需为推荐权重、推荐池、置顶、隐藏预留；Phase 0 不实现随机算法。

## 5. Skill 详情页

标题先显示中文传播标题，再显示 `original-skill-name`。内容顺序为：简介；作者、来源、分类、标签；主封面和图片集；ZIP 与安装操作；功能；场景；子 Skills；用法和 Prompt 示例；效果和实测；风险；原始 GitHub、版本、Commit、来源；相关 Skill。

至少一张封面，附加图选填且总量最多八张，支持普通图片和 GIF；第一版不直接托管视频但可保存外部链接。每张图片应记录来源，可来自 AI、原作者、社区或团队实测。案例视觉权重不得超过 Skill，不建立复杂独立案例 CMS。

后台数据可以保留亲测、编辑精选、验证、社区推荐等状态，但第一版公开卡片及详情首屏不展示。

## 6. Skill Pack 与父子关系

- 原生 Skill 包：原仓库/文件夹本身含多个相关 Skill。
- 编辑组合包：Catnip 按目标整理多个来源或 Skill。
- 管理员决定重要子 Skill 是否有独立详情页；数据支持父子关系与独立页面开关。
- 第一版只下载整个包，不勾选单个子 Skill 重新打包；详情可列子 Skill，首页不强制标示类型。

## 7. 下载 ZIP

下载 ZIP 与安装到 Agent 是详情页同等重要的主要操作。单项 Skill 打包对应文件夹；原生包打包整个原生包；编辑包打包管理员整理的完整组合。

标准结构：ZIP 外层包含原始 Skill 文件夹、`Catnip-安装说明.md` 和 `Catnip-来源信息.json`。原始文件夹内部保持原样，不插入 Catnip 文件，不修改原始 `SKILL.md`，不影响 Claude Code CLI 或 Codex CLI 发现。页面组件不得执行打包，打包属于独立下载服务层。

安装说明可记录中文介绍、原名、作者、仓库、Catnip 页面、版本和两个 CLI 的安装说明。来源 JSON 可记录 originalName、originalAuthor、sourceUrl、repositoryUrl、sourceCommit、license、downloadedAt、catnipPageUrl。

每条资源保存作者、原始来源、GitHub、License、版本/Commit、下载文件、`downloadEnabled` 和管理员备注。平台不自动作法律结论，不按 License 自动允许或禁止，由管理员显式决定镜像下载。

## 8. 安装到 Agent

第一版只支持 Claude Code CLI 与 Codex CLI，并支持当前项目和全局安装两个范围。第三方 Skill 优先用原作者 GitHub 仓库，必须保存仓库及 Skill 路径/名称，命令不能依赖中文标题；Catnip 原创或编辑包使用 Catnip 维护的来源。

Phase 3 实现前必须实际检查 `npx skills --help` 和 `npx skills add --help`，按当时真实参数开发。命令生成集中在 `lib/install` 或等价领域服务，不散落于 React 组件。

## 9. 统计与后台边界

阅读量、ZIP 点击、命令复制和 GitHub 跳转可预留；Phase 0 不实现，阅读量可推迟到 Phase 6且不要求早期去重算法。

未来后台支持手动资料+ZIP，以及粘贴 GitHub 地址后辅助读取仓库和 SKILL.md。所需能力包括预创建管理员账号、登录、草稿/发布/下架、CRUD、分类标签、图片和 ZIP、作者来源、仓库和安装参数、子 Skill、版本/Commit/License、下载开关、推荐线索和基础统计。Phase 0 只定义边界。

## 10. 品牌规则

本轮只使用“Catnip 薄荷猫”文字品牌并预留可替换资源位置。正式 Logo、吉祥物和社交分享图由团队后续提供；不生成、不确定、不以 emoji 冒充、不从网络随意下载猫图。约定见 `public/brand/README.md`。
