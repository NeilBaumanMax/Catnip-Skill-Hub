# 施工工作流

## 开工

1. 按 AGENTS 必读顺序读取文档。
2. 依次记录 `pwd`、目录/文件、Node/npm、Git 仓库/分支/状态/remote/身份/HEAD/日志。
3. 验证 `ssh -T git@github.com` 输出账号为 NeilBaumanMax；只使用指定 SSH origin。
4. 对本地与远端执行只读历史分析，保护未知改动；遇到冲突或缺身份/权限即停。
5. 向 DEV_PROGRESS 和当前层进度文件追加具体开工计划。
6. 记录分支、状态、HEAD、remote；创建唯一时间戳备份分支，成功 push 后切回开发分支并复查。

## 施工与验证

1. 只做当前 Phase 范围，明确文件边界并使用最小依赖。
2. 在 LOG 保留实际变更和每次验证记录。
3. 失败时停止扩展，记录首次失败与摘要，定位、修复、复测；需要时执行全量验证。
4. 通过后检查架构、依赖、阶段、脚本、Git、产品、身份品牌、密钥和用户文件漂移；修正后复测。

## 收尾

1. 停止本轮长跑进程。
2. 更新 LOG、DEV_PROGRESS、当前层进度和 HANDOFF。
3. 检查 `git status --short`、`git diff --check`、`git diff --stat` 和完整差异。
4. 仅明确暂存审阅过的本轮文件，不提交环境、密钥、依赖或构建产物。
5. 创建有意义的提交，push 当前开发分支；禁止 force push。
6. 核验最终 HEAD、分支、远端跟踪、日志和工作区，再把最终提交与 push 状态回写日志。若回写产生新提交，也必须再次 push 并记录最终事实。

## 追加与漂移

追加式文件不改写旧记录。规范可修正，但须记录原因。测试成功并不自动代表完成；只有文档、GitHub 和交接门禁均完成才可报告。
