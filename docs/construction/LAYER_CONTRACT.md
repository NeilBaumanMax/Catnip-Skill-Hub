# 分层契约

## 允许依赖方向

`页面/组件 -> 应用用例或领域服务 -> 领域模型与端口 <- 基础设施适配器`

- 页面可依赖展示组件、应用服务及只读 DTO。
- 安装与下载服务可依赖 Skill 领域中的稳定标识、来源和授权信息。
- 数据与存储适配器实现领域或应用层声明的接口。
- 认证服务可为管理用例提供管理员身份和权限判断。
- 纯领域模型只能依赖 TypeScript 标准能力和同领域纯模块。

## 禁止依赖方向

- React 页面或 UI 组件不得直接打包 ZIP、拼接安装命令、写数据库或绕过服务层写入。
- 数据库层不得依赖 React；存储层不得依赖具体页面。
- 下载层不得修改原始 Skill 文件夹或原始 `SKILL.md`。
- 安装层不得依赖中文展示标题，必须使用稳定的仓库、路径或名称。
- 客户端不得包含管理员密钥、真实密码、Token 或服务端凭据。
- 领域层不得依赖 Next.js 路由、数据库 ORM 或具体对象存储 SDK。

## 公共前台契约

负责首页、分类、搜索、详情、推荐线索表单及展示交互。普通访客读取公开资源和触发公开动作，不需要普通用户身份。公开写操作必须通过受控服务入口。

## 管理后台契约

负责预创建管理员的登录、资源 CRUD、草稿/发布/下架、分类标签、文件图片和推荐线索。只有管理员可以公开发布；新资源必须先为草稿。

## 领域与基础设施契约

- Skill：资源身份、类型、Pack/子项关系、状态、分类标签、作者来源、版本、图片与下载授权。
- Install：Agent、范围、来源、命令验证；Phase 3 前先核验真实 CLI。
- Downloads：原始内容只读打包、Catnip 外层文件、授权和事件。
- Storage：文件读写接口和可替换适配器。
- Data：Repository、查询和事务；不泄露 ORM 到 UI。
- Auth：仅管理员身份、会话与授权。

## Phase 4 已实现契约

- 管理页面与 API 只能依赖认证服务和管理员应用服务；客户端不得导入 Runtime Repository。
- 管理员应用服务依赖 `SkillRepository` 端口，不依赖 React、Next.js Cookie 或具体数据供应商。
- 进程内 Repository 是开发适配器且返回深拷贝；后续持久化适配器必须保持同一端口语义。
- 认证配置、密码哈希和签名密钥只在服务端读取；Cookie 验证和所有写操作授权不得由客户端替代。
- 公开目录当前不依赖进程内管理仓储；在持久化查询适配完成前，管理端状态变化不得声称已实时发布到公开站点。

## 变更检查

新增依赖前说明所属层、调用方向和 Phase；如契约需变更，先改规范并在 LOG 记录原因，再实现和复测。
