# Catnip Skill Hub UI 专项规划

## 文档状态

- 状态：已批准进入施工准备，尚未开始 UI 代码修改。
- 工作分支：`SKill-hub-ui`。
- 设计基线：`059ab6a50f5cba20aa756811e36d2ad1afee2c28`。
- 参考对象：Marvis 技能广场、腾讯 WorkBuddy 技能广场。
- 产品约束：以 `docs/product/PRODUCT_REQUIREMENTS.md` 为准；本文只定义前端表达，不扩大产品范围。

## Design Read

把它理解为：面向中文 Agent 用户的 Skill 发现型产品界面，以 WorkBuddy 的成熟导航、分类与操作逻辑为骨架，以 Marvis 的内容画廊感和瀑布流浏览节奏增强发现体验，并由 Catnip 薄荷猫的中文策展与来源可信度形成独立身份。

设计参数：

- `DESIGN_VARIANCE: 6`：有编辑感和错落节奏，但不牺牲可预测操作。
- `MOTION_INTENSITY: 4`：动效服务状态反馈与层级转换，不做持续漂浮和表演式滚动。
- `VISUAL_DENSITY: 6`：进入页面后快速看到内容，同时保留封面、标题与来源的呼吸空间。

## 设计结论

不是把两套界面拼在一起，而是明确分工：

| 维度 | 主要借鉴 | Catnip 的处理 |
| --- | --- | --- |
| 信息架构 | WorkBuddy | 搜索、精选、分类、排序、内容区层级清楚，但只保留 Catnip 第一版范围 |
| 内容发现 | Marvis | 封面优先、错落高度、连续浏览，让 Skill 像创意内容而不是文件列表 |
| 产品身份 | Catnip | 中文传播标题、管理员策展、原作者与来源可追溯、Skill 始终是主角 |
| 操作决策 | Catnip 需求 | 首页负责发现，详情页负责下载和安装，不在卡片上放直接安装按钮 |

一句话方向：`WorkBuddy 的骨架 + Marvis 的浏览节奏 + Catnip 的中文策展身份`。

## 借鉴与拒绝清单

### Marvis

保留：

- 图片和封面承担第一识别层，标题与介绍承担第二解释层。
- 不同高度与宽高比形成内容节奏，避免等高卡片墙。
- 进入页面后尽快展示实际资源，支持持续向下发现。
- 分类、搜索和排序靠近内容区，不用大型 Hero 抢占首屏。

拒绝：

- 不建立“案例广场”主线；案例仍只属于 Skill 详情辅助模块。
- 不引入“发布案例”“我的案例”、点赞社交和用户内容社区。
- 不让封面大字与卡片标题机械重复。
- 不把视觉封面做成无法识别真实功能的抽象装饰集合。

### WorkBuddy

保留：

- 顶部资源导航、持续可见搜索和当前上下文状态。
- “精选内容 + 完整目录”的两级发现结构。
- 分类、来源、排序与结果区之间清晰的层级。
- 资源来源、热度与状态信息的低优先级表达。
- 不同资源结构使用不同密度，而不是所有页面强行同一种卡片。

拒绝：

- 不照搬深色主题、灰色密集卡片和腾讯业务视觉。
- 不建立专家、专家团、连接器、MCP 或 Prompt 市场。
- 不在首页卡片放“+”安装动作；首页整卡只进入详情。
- 不复制“推荐 / SkillHub / 套件”这套来源型标签。Catnip 首页不强调单项、原生包、编辑包的技术差别。
- 不使用无尽横向分类且缺少边缘提示的交互。

## Catnip 新信息架构

### 全站顶部

1. 可替换品牌位与文字品牌 `Catnip 薄荷猫`。
2. `探索`、`分类` 两个清晰入口。
3. 桌面端持续可见的紧凑搜索；移动端折叠为可展开搜索区。
4. `推荐 Skill` 次级行动。
5. 不显示登录、我的 Skill、安装数量或用户账户入口。

### 首页

1. 紧凑引导：一行价值主张，不建立大型 Hero。
2. 精选推荐：3 至 4 个可换一批的资源，承担 WorkBuddy 的“精选”层级；内容仍来自管理员推荐池。
3. 发现控制条：五个固定主分类、可用标签、当前结果摘要与真实可支持的排序。
4. 编辑式瀑布流：承担主要浏览区，封面驱动且保持整卡可点击。
5. 空结果：解释当前筛选，并提供清除条件。
6. 页脚：品牌、管理员筛选说明、来源与推荐入口。

排序只显示已有数据语义能兑现的选项。第一批施工保持“推荐”默认；“最新”“热门”必须在领域数据和统计定义确认后才能开放，禁止做无效控件。

### Skill 卡片

信息顺序：

1. 视觉封面；
2. 中文传播标题；
3. 一句话功能介绍；
4. 原作者或来源；
5. 主分类与一个代表标签；
6. 阅读量等低优先级数据。

规则：

- 整张卡片进入详情，首页无下载、安装或“+”按钮。
- 中文标题与一句话介绍不得复述。
- 不在首页用醒目标签强调单项 Skill、原生包和编辑组合包。
- 封面必须有稳定宽高比和焦点区域；没有正式图片时使用明确标记的可替换演示构图，不伪造品牌资产。
- Hover 只增强封面与标题的关联，不让卡片大幅位移。

### Skill 详情页

保持产品需求规定的信息优先级，不照搬市场详情模板：

1. 中文标题、原名与一句话介绍。
2. 作者、来源、分类、标签与低优先级统计。
3. 主封面与效果图片集。
4. 下载 ZIP 与安装到 Agent 的同级行动区。
5. 功能、场景、子 Skill、用法、效果、风险、版本来源、相关 Skill。

桌面端可让行动区在阅读主内容时保持可见，但不得遮挡正文；移动端改为正文内操作区，不使用遮挡内容的永久底栏。

### 推荐页

- 延续全站品牌、导航、表单控件与状态反馈。
- 明确说明推荐只形成线索，不自动创建草稿、不自动公开。
- 成功、错误、提交中和重复提交状态都必须有明确反馈。

## 编辑式瀑布流方案

不使用 CSS Columns 作为主方案，因为它容易造成视觉顺序与横向阅读预期不一致。也不在首轮引入运行时高度测量库。

采用 CSS Grid 的“编辑式瀑布流”：

- DOM 顺序就是阅读、键盘和屏幕阅读器顺序。
- 由资源封面元数据映射为有限的 `portrait`、`standard`、`wide` 比例与行跨度。
- 大屏默认 4 列；中等桌面 3 列；平板 2 列；移动端 1 列。
- 置顶或精选只影响内容顺序，不把网格做成不可预测拼图。
- 第一批复用现有 `coverSize` / `coverTheme` 表达，无需立即修改数据库；接入真实图片后再由图片元数据驱动。
- 筛选后保持 DOM 重排清晰，不使用跨屏飞行动画。

## 视觉系统

### 色彩

- 主界面采用偏冷的中性浅色底与深石墨文字，避免当前暖米色手作风和 WorkBuddy 的纯黑重压感。
- 全站只保留一个 Catnip 薄荷绿色强调色，用于选中、焦点、主要行动和少量品牌识别。
- 同时规划浅色与深色令牌；首轮默认浅色，深色必须经过同等页面验收后才开放切换。
- 图片本身承担色彩变化，UI 外壳不使用多色渐变制造“AI 感”。

### 字体

- 中文与拉丁统一使用现代无衬线系统，优先当前系统字体与可自托管方案。
- 移除当前 Georgia/宋体式展示字作为主视觉，避免把创意感误解成随机衬线。
- 标题依靠字重、行高、宽度和留白形成层级，不依靠全大写英文装饰。

### 形状与材质

- 卡片圆角统一在 14 至 16 像素范围；按钮和筛选胶囊可使用全圆角。
- 只在浮层、粘性顶部和关键精选卡片使用轻微阴影；普通网格主要靠间距、背景和边线分组。
- 玻璃模糊只允许出现在粘性导航，并提供无透明效果的回退。
- 正式 Logo 与吉祥物继续使用可替换位置，不用 emoji 或网络猫图替代。

## 交互与动效

- 搜索与筛选状态继续写入可分享 URL。
- 精选“换一批”只调用既有推荐规则，不伪造新算法或用户画像。
- Hover：160 至 200ms，封面轻微缩放不超过 1.02，标题或边线增强。
- Press：约 120ms，使用轻微缩放或下压反馈。
- 筛选切换：淡入和位置过渡不超过 200ms；避免逐卡长延迟。
- 页面首次进入不做大面积飞入、模糊揭示或无限循环动画。
- 完整支持 `prefers-reduced-motion`，功能不依赖动画完成。

## 响应式与可访问性

- 约 1440px：4 列主网格，精选 4 项。
- 约 1024px：3 列主网格，精选 3 项。
- 约 768px：2 列主网格，搜索与导航重新分组。
- 约 390px：1 列主网格，分类横向滚动并有边缘提示。
- 触控目标不小于 44px，分类与搜索可用键盘操作。
- 焦点样式不能只靠颜色；内容顺序和 tab 顺序必须一致。
- 图片提供准确替代文本或被标记为装饰；文字对比达到 WCAG AA。
- 动态结果区使用适当状态说明，不在每次筛选时抢夺焦点。

## 性能约束

- 首页首屏只加载可见封面，非首屏图片延迟加载。
- 使用 Next.js 图片能力前先确认远端图片来源策略；禁止开放任意远端域名。
- 不为了瀑布流引入大型布局依赖，不为了轻动效引入全局客户端状态。
- 交互叶节点才使用 Client Component；首页目录与详情主体继续优先服务端渲染。
- 防止筛选和图片加载导致 CLS；封面容器必须预留尺寸。

## 施工批次与停点

### UI-1：视觉令牌与全站骨架

- 建立色彩、字体、间距、圆角、阴影和焦点令牌。
- 重构顶部导航、紧凑引导与基础页面容器。
- 停点：桌面/移动骨架截图、键盘路径、lint/typecheck/build。

### UI-2：首页发现系统

- 实现精选推荐、五类目控制条、真实筛选状态和编辑式瀑布流。
- 实现卡片、空结果、加载布局与 reduced-motion。
- 停点：首页 1440/1024/768/390 视觉验收，确认没有首页直接安装或下载。

### UI-3：详情与推荐页统一

- 重排详情首屏、图片集、操作区、正文与来源信息。
- 统一推荐表单、状态反馈和相关 Skill。
- 停点：首页、详情、推荐页跨路由一致性与完整功能回归。

### UI-4：最终打磨与浏览器验收

- 修复响应式、无障碍、性能和真实内容边界问题。
- 使用局域网入口进行桌面与其他设备人工验收。
- 停点：测试、视觉截图、文档漂移、LOG/HANDOFF、提交与 push 全部闭环。

Neil Bauman 要求每完成一次 Phase 停下汇报。以上 UI 批次属于当前前端专项内部里程碑；任何批次完成后都必须停下汇报，未经明确继续不得进入下一批。

## 每批验收门禁

- `npm test`
- `npm run lint`
- `npm run typecheck`
- `npm run db:check`
- `npm run build`
- `git diff --check`
- 首页、至少一个详情页、推荐页的浏览器检查。
- 1440、1024、768、390 四个视口的关键截图检查。
- 键盘焦点、触控目标、对比度、reduced-motion 和空结果检查。
- 核对管理员为 Neil Bauman、品牌为 Catnip 薄荷猫、Remote 正确、无真实秘密、无后端/部署越界。

## 当前非目标

- 不改数据库、认证、ZIP、安装命令、导入、统计和服务器部署。
- 不引入专家、连接器、MCP、Prompt 或社区市场。
- 不创建正式 Logo、吉祥物或站内 AI 生图。
- 不复制参考产品的品牌、图片、图标或文案。
- 本规划轮不修改 `src/`、依赖或运行环境。

## 回滚

- 每个 UI 批次从已 push 的前一基线创建独立备份。
- 失败变更优先 `git revert <bad-commit>`，然后执行该批全部门禁。
- 不删除 `frontend/visual-optimization` 或其他历史分支；它们保留作失败方案证据。
- 不使用 reset、clean 或 force push。
